# 视频笔记交付格式

写作者为每条视频只写一份证据版 `note.md`（沿用 `note.scaffold.md` 的标题、频道和日期），与 `selection.md`、文稿、状态一并留在任务目录。通过两道检查与独立复核后，由渲染器生成阅读版到频道文件夹（`〈发布日期〉 〈频道〉 - 〈标题〉.md`）。

## 生成阅读版与交付

```text
python scripts/verify_note.py --job "<任务目录>" --with-coverage
〈两道通过后交独立 Task 复核并处理同一批意见〉
python scripts/render_reading_note.py --require-review --task-dir "<任务目录>" --output-dir "<频道目录>"
```

三条有状态命令会读写任务状态：`verify_note.py --job`、`coverage_check.py --job`、`render_reading_note.py --task-dir --output-dir`（兼容 `--output` 与 `--keep-frontmatter`）。正式送检会在任务锁内先规范「原文依据」引文头部（只整理时间戳、画面标签、空格、括号冒号和 `>`，不改原话），纯格式整理不计轮次。新任务须等 `next_step: write-note`，且使用持久化的 `screen_ocr.mode` 与校验一致的 `screen.txt`。

## 动笔前通读和取舍

通读全文，按原顺序切成意思完整的单元，手写 `selection.md`：`时间范围 | 类别 | 留或略 | 一句理由`。语音范围左闭右开、首尾相接、连续覆盖全文；画面行类别以 `[` 开头。

- **必须留。** 核心主张、步骤及顺序、讲者清单、支撑数字、具名案例、适用前提/地区/版本，以及必要的方法、组件、指标和可执行代码/命令。
- **应当略。** 寒暄、广告口播、纯重复和离题闲聊；重复段若新增条件、例外或结果，仅留新增信息。短于 5 秒的片头片尾并入相邻单元。
- **正文只用「留」。** 清单保留项目和顺序；可独立略去的列举写清原编号并在「本文略去」列时段。具名案例留谁/项目、之前怎样、做了什么、之后怎样及原口径量化结果。
- **解释留用的技术要素。** 正文保持 100% 讲者内容，不插独立术语框打断顺读；讲者后文给过的白话解释可前移揉进句内，但须挂对应原话 `⏱`。整理者补充统一写 `> [!note] 术语：…` 块，由渲染器汇总至文末 `## 术语速查`（首行固定声明非讲者原话，建议全篇 ≤12 条、每条 ≤60 字，严禁复述正文或藏入视频事实）。通俗版只为影响理解的陌生术语建条（每框硬限 ≤2 句、≤120 字、禁 `⏱`）；精炼版只解释视频自造词、冷门专名、首次出现且需要解释的缩写，以及讲者用法与通行定义不一致的词（PR、CTO、LLM、IDE、JVM 等常规词不解释）。
- **画面独有内容。** 把讲者未念的表格、清单、代码、标注逐项写入 selection，如 `04:27 | [画面] 保存湿度表 | 留 | 可查湿度范围`。带幻灯片分组时每组另抄编号和起始时间，如 `04:27 | [幻灯片 3] 保存条件 | 略 | 本文只讲数字馆藏`。S01 优先项目行，再用所属幻灯片决定。

S01 要求范围连续有序，至少 3 个留用语音单元；引文按 cue 区间重叠（±1.5 秒容差）命中所有覆盖到的留用槽位，超长留用语音单元按虚拟子窗切分计命中，须命中 `max(3, ceil(0.9 × 槽位数))`。长视频还须通过 C02 三个四分位。略项超 50% 仅报 WARN。

## 正文、原文依据和检查

- **位置即边界与连贯段落。** 正文 = 100% 讲者内容，文末 `## 术语速查` = 100% 整理者补充。每段写 2–4 句连贯中文（口语与画面合一讲一次，不机械重复“画面显示/幻灯片写着”）；适用范围（地区、版本、前置条件）前置到开篇或对应节首句。
- **按 `⏱` 簇分片绑定。** 相邻 `⏱` 合并为簇（建议 ≤3 个锚点/簇、去代码片长 ≤220 字），`C04b`/`C04c` 按片核验而非整段取并集。段首过渡自然并入首片；段尾 ≤80 字或导语段 ≤120 字且无新可核查事实（或同 `###` 内已有回指）可不另挂 `⏱`。先配同秒引文，否则取 15 秒内唯一最近者；同文字体系每片须共享至少 3 个内容词元。
- **自然中文，不硬塞括号。** 仅在无通行中译的专名首现、读者需用于检索的术语或代码标识符时保留英文括号；禁止写 `50%（50%）`、常见词括号或把 ASR 错词硬括进正文。
- **引文 → 文稿。** `## 原文依据` 为最后一个 H2，用 `python scripts/extract_quote.py "<任务目录>" START END` 提取连续原话（语音 ≥40 字符，戳距 ≤15 秒）；画面用 `--screen START END` 提取可信 `[画面]` 行（禁引 `[画面?]`）。每条文末引文必须被正文使用且只列一次。
- **数字、专名与代码 → 引文。** 标记块外所有事实数字、专名和行内/代码块小写 API 标识符均须落入对应片的语音/画面引文或 `原文出入`（仅「这场在谈什么、谁」可直接用 `published`/`channel`/`title`）。保留原口径、单位、比较对象和条件。
- **直接写视频内容，合法标疑。** 错字/口述代码/证据冲突统一走 `> [!warning] 原文出入`，不在正文叙述写作者如何核对或筛选；面向读者的边界说明（如“视频未展开”“视频未给出完整命令”）正常写清。
- **取舍与缺钟。** 正文不得转述「略」单元；缺可靠时间戳须停并报「缺时间戳，请用带时间戳的转写重跑」。英文文稿对应中文正文超每词 1.2 汉字仅报长度 WARN，不阻断交付。

### 精炼版

精炼版少建术语条、缩短铺垫，「先记住一句话」仍用白话并交代适用范围。尾节可选；若保留收尾应用节，用 `## 可以怎么用、可以拿去讨论什么`（1–3 项，每项有 `⏱`、≤2 句，写明团队前提）。

### 两种标记块（禁 `[!tip]`）

```markdown
> [!note] 术语：〈文稿可追溯词条〉
> 〈≤2 句、≤120 字、禁 ⏱；只写通识定义，不复述正文，不藏视频事实。（Claude 补充，非视频内容）〉

> [!warning] 原文出入
> 字幕写作 A，实为 B。
> 口述代码｜口述原文｜`规范代码`
> 存疑｜「前一段唯一逐字锚」｜≤50 字中性说明（不替讲者选边）
```

1. **术语块**：按斜杠/括号拆别名、连字符视同空格，至少一种写法须在文稿或更正结果出现；渲染器按首次出现汇总至文末 `## 术语速查`（建议全篇 ≤12 条、每条 ≤60 字）。
2. **`原文出入` 三行型**（取代旧 `字幕更正`，紧跟对应非 callout 段落/列表项）：
   - **行型 1（拼写/大小写规范化）**：`字幕写作 A，实为 B` 或 `画面写作 A，实为 B`；阅读版静默隐藏。若两侧数字/版本不等（如 `3.5` vs `3.6`）、或无第二来源的专名大改/补全姓氏，校验器强制报错，必须改用行型 3；错拼写 A 不得漏进正文。
   - **行型 2（口述→代码）**：`口述代码｜口述原文｜`代码``；画面已有代码则直引画面不写本行型；全文凡用过本行型，阅读版仅篇首加 1 句「部分代码按讲者口述整理」，同时为正文小写 API 标识符提供依据。
   - **行型 3（实质冲突/信息缺失）**：`存疑｜「唯一锚」｜说明`（≤50 字、不含右括号）；锚须为前一段唯一逐字子串、不跨 `⏱`、不落入代码块/行内代码/表格/标题/链接；渲染器在锚所在句末标点前就地插入 `（存疑：说明）`。**行型 3 不豁免 C04c**。

## 五种类型模板

中间小节下可用 `###` 分主题（阅读版自动附轻格式时间范围 `### 标题 · 12:30–18:45`）。

### 讲座、课程

用 `## 主线论点` 下的主题 `###` 与连贯段落（每段 2–4 句）组织主线，**不再按 `1..105` 逐句编号**。完整保留留用清单、步骤条件和具名案例的前后量化结果。

### 访谈、对谈

用 `## 话题` 分 `###` 写各话题（`## 意见不一致的地方` 无分歧时可省略）。在「这场在谈什么、谁」交代全部角色；**视频标题中出现的每位人物均须在正文有明确交代**。取消“其余默认是嘉宾”假设：无说话人标签时按上下文审慎归属，无法确认写清“未区分说话人”或用 `存疑` 标注，不硬猜单嘉宾。

### 大会演讲、发布会

用 `## 发布或主张了什么` 概览核心主张，用 `## 主线讲了什么` 按主题/步骤分 `###`（含现场演示与数据口径）；`### 只是口头声称` 仅在确有未验证预告时保留于末尾，否则省略。

### 产品演示（≤10 分钟）

用 `## 演示了什么` 按实际操作顺序写留用步骤与屏幕结果，用 `## 关键数字与条件` 列前后量化指标、单位与适用条件。

### 教程、实操

`type: 教程`，用 `## 操作步骤` 按执行顺序分 `###` 写清前置环境、步骤与预期输出。**必须还原完整可执行的代码块或命令**（画面可见直引 `[画面]`；纯口述经 `原文出入` 行型 2 登记重建）；若原视频未给出完整参数、配置或命令，明写“视频未给出完整命令/参数”，严禁自行补全。
